# 固定交付：报表、逻辑总结、干净正文

完整逐图/段落写作按下列顺序交付。局部纠错只给受影响内容，纯审查不自动改稿。展示顺序与内部执行顺序不同：写作和检查完成、最后自然化、验收及回填后，才输出最终报表。

## 1. 报表包

### 图与段落逻辑

记录当前范围、稿/图版本、继承/修改点，本图在全文的任务，上文已建立什么，图内模块如何组织，本段主信息、可得结论及边界，与下文关系，以及近期基底和当前任务覆盖状态。结构可为并列、对照、时间演变、整体到局部、状态转换或互补验证，依真实证据确定，不固定一种链。

### 逐句九项

| 字段 | 必须说明 |
|---|---|
| 1 最终句ID/位置 | 稳定ID、段落与顺序、段首/展开/解释/收束等位置 |
| 2 类型与功能 | M机理解释/T技术描述与证据/L衔接组织，辅助作用，测试子类型 |
| 3 自己的证据 | 图/子图、样品状态、观察或数值、证据ID和核验状态 |
| 4 实际来源 | source_id、论文/DOI、日期、原文位置、实际阅读范围；多来源各说明动作 |
| 5 必要短摘 | 准确且可定位的最少原文片段，不长段复制 |
| 6 中文义/结构动作 | 原文什么意思，怎样安排对象、条件、观察、比较或限定 |
| 7 本稿最终句 | 与最后正文逐字一致；英文保留相应中文信息组织 |
| 8 作用及前后关系 | 为什么写，接住前句什么、推进什么、在段落的位置 |
| 9 改写及边界 | 保留/替换/删除/新增，不能迁移的事实，不报任意改写百分比 |

一句可有主类和次功能，不固定M/T/L排列，不为类型凑句。T按本部分的实际任务分为T-方法/制备、T-观察/结果、T-计算等；方法步骤不是已获得的测试结果。测试子类含XRD、SEM、TEM、XPS、CV、EIS、性能等；同测试也须核对对象、状态和适用模型。L若新增科学判断仍需证据。

可拆成以句ID关联的两表；自己的观察/计算、作者提供或确认的方法、原创承接及沿用确认稿如实标注，无需硬配母句。允许一对多、多对一、多对多。不能为表格完整事后假找原文。表达示范来源不自动进入正文正式参考文献。

### 执行溯源

用简表记录实际步骤、调用/借鉴/新组织、实际读取或执行范围、输入/产物、完成/局部/未执行/不可用。没有实际运行不能说机检通过；读部分规则不能说完成ARS全审。共享来源ID和确认账本，小改只更新变动项。

## 2. 简短逻辑总结

用一至两句说明证据顺序和句间关系，让作者审核连贯性。它是审查材料，不自动追加论文段尾。无需每段都问问题或预告下一图。

## 3. 完整正文、图注和计数

提供末轮学术自然化后的连贯正文，不夹分类、写作说明或待核旁白。图注任务附相应主图或支撑图注；正文/图注分别计数。英文附必要中文释义，不冒称回译独立证明保义。

最终自然化后，句表与正文逐字一致；若拆合、调序、删句，回填句ID、命题、证据和来源，重算字数。未确认事实不能包装成结果，候选未获作者接受不能自动升为确认稿。

## 4. 可选机器交付记录

delivery-check支持JSON对象，sentences列表每项含sentence_id、paragraph_id、order、text、evidence_ids、source_ids；paragraphs列表每项含paragraph_id、text。同段按order排序，直接拼接text与段落逐字比较；英文句间空格须存在text中，不能依赖程序忽略空格。

source_ids可空，但必须明确basis为own_observation、own_calculation、author_provided、author_confirmed、author_transition或retained_accepted。自己的观察/计算、作者提供或确认内容须有非空且有效的evidence_ids；作者确认仍不等于原始数据已验证。纯组织承接可不引证据，沿用确认稿另给basis_ref。证据ID须指向当前evidence.json中存在记录；来源ID须指向sources.json。允许多对多，缺证据不能用空数组掩盖关键主张。可选propositions记录人工检查的命题槽位，脚本不验证其语义。

这份结构化记录辅助核对最终交付，不替代作者可读的九项映射表。脚本具体参数与支持字段见--help，不能将结构校验通过写成科学验证通过。

交付JSON内部的句段一致不能代替实际Markdown、纯文本或Word交付核对。正文另存文件或在界面呈现时，须另比较最终显示的正文与句表/JSON；未完成这一步，只能报告“JSON内部一致”。脚本不自动解析Word或Markdown正文区，也不核验所标basis的科学真实性。
