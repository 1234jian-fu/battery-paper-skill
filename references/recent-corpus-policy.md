# 每稿至少60篇近五年原始研究基底

## 1. 数量与适用范围

每篇新稿的默认最低数为60篇，计数目标同为60篇，按唯一正式原始研究计数。目标是覆盖本研究的方向、材料构筑、测试表达、过程分析、性能和模型等实际写作任务；不能用无关顶刊文章填数。综述可帮助定位方向，不能替代该原始研究基底。作者明确变更数量或范围时，记录变更及其依据。辅助脚本使用自定政策须在project.json记录corpus_policy_override={authorized_by: user, decision_ref: 非空决定记录}，并给合法corpus_policy；没有明确变更依据的旧政策仍提示needs_policy_update，不能自动覆盖。

这个数量是整篇稿件的共享基底，不是每幅图都另找60篇。继续写作或小改时复用仍有效且已核查的记录；有新图、方向变化或窗口失效时增量补充。历史种子库只能提供入口，不能直接以条目数宣称本项目达标。

## 2. 滚动五年与日期

记录任务使用的`as_of_date`，取当前客户端日期或作者明确指定的研究截止日。默认范围为该日向前五年（含边界）至该日。闰日回推遇非闰年时用2月最后一天。示例：2026-10-29对应2021-10-29至2026-10-29，而不是固定“2021年至2026年”。

优先采用出版社正式首次在线日期；若明确给出first_online_date，不得再用较晚卷期或publication_date覆盖它。记录`date_basis=publisher_first_online`及核验入口。正式online early view可以纳入，未正式发表的预印本不进入默认基底；卷期年份不能覆盖更早的正式online日期。来源冲突时先核对；未来日期不计。

只有年份或月份时按日期区间处理。若整个区间均在窗口内，可判日期范围合格；跨窗口下界或当前日期上界时标`needs_date_verification`。不为2021年条目虚造月份，也不把只有年份的当前年条目无条件认定已发表。

## 3. 合格基底的最低记录

每条同时满足以下条件才计入“已核读合格基底”：

1. 正式原始研究身份明确，元数据已核对；DOI去重，或无DOI时有经核验的唯一论文身份；同研究同时出现DOI和无DOI记录时，用共同unique_work_id关联并按一篇处理。source_id只标记录，不能代替论文身份，重复source_id必须先解决。
2. 发表日期范围在滚动五年内，日期来源已核验。
3. 与本研究同细分方向，或共享当前需要学习的测试/论证任务，并写出适配理由；仅背景不计。
4. 实际读过相关正文与对应图注，记录准确位置、中文含义及段落推进/数据表达。无需冒称整篇逐字精读，但摘要、索引、技能卡、他人概述不足以计入。

同一研究的PDF、HTML、预印本及正式版不重复计数；更正/撤稿等附属记录关联主文，不充当新的一篇。存在发表身份或有效性疑问时标待核。

推荐字段：

```text
source_id / doi / unique_work_id / title / source_type=primary_research
bibliographic_status=verified / publication_date / publication_date_verified=true
date_basis=publisher_first_online / date_source_url
topical_fit=direct|shared_test / fit_reason
read_scope=relevant_body|full_main_text|full_main_and_SI
exact_locations / chinese_meaning / source_paragraph_move / source_data_expression
linked_figure_tasks / accessed_at / local_text_hash
```

`publication_date`支持YYYY-MM-DD、YYYY-MM或YYYY，保留真实精度。上述状态是人工核查记录。ID、拟合理由、中文含义和写作动作须为非空文字，定位为非空文字或非空文字列表；空白、布尔值和对象不能充当已填写的阅读记录。任务ID也须为非空字符串，不能把数字或对象强转为标签。脚本只能检查记录完整性和日期范围，不能证明已经阅读或语义契合。

date_source_url须为含主机名的HTTP/HTTPS入口；脚本只检查基本语法，不联网验证页面内容或权威性。明确提供但无效的first_online_date（包括布尔值、0或空容器）标为日期未知，不回退到较新的卷期日期；缺省、null或空字符串才允许回退。

## 4. 先读图，再定向找表达

读当前图稿→识别对象/状态/指标→拆出需要学习的动作→检索近期契合原文→核读对应段落/图注→中文译意→对应本图证据→起草→专业校正与语言精修。

表达任务要具体，例如“相同时间的接触角比较后如何限定结论”“XPS不同阶段比例如何与后续功能证据衔接”“迁移路径与连续云图如何保持尺度边界”。满足60篇数量但没有当前测试的来源映射，仍不表示本图已准备完成。

每句话可依赖本研究事实、近期来源结构或作者组织；不强行从60篇中给每句分配一个原句。需要一篇来源承担几个动作时分别定位，避免反复只用少数论文但宣称整体综合了几十篇。

## 5. 近期写法校准

把最新的契合原文作为当前表达范本：比较其小标题范围、段首任务、数据密度、判断动词、证据邻近及收束方式。简洁、科学、准确优先于追逐流行词；不能臆造某期刊统一的标题字数或句式。文献本身也可能过度推断，需按本研究证据校正。

旧写法卡中可继续使用一般测试约束、计量规则和论证动作；进入当前具体原文映射前，须用近五年合格来源重新对应或替换。较早经典方法来源在科学或方法说明确有必要时可另列并解释用途，不计入近期60篇基底，也不冒充近期表达范本。

## 6. 真实进度与不中断原则

分别报告：`已发现总数｜日期合格候选｜相关原始研究｜已核读合格基底｜当前图已映射任务数`。作者审阅界面只给必要摘要，完整账本保留项目内。

不足60篇时显示真实缺口；60篇及以上仅表示数量达标，仍须检查当前表达任务的原文对应和自己的证据。访问失败、日期待核和未读正文都单列。可先交明确标记的阶段性结构或候选，不用虚假数量撑起“已完成”。作者只要方案、小改或审查时，先完成该任务，不无故将其升级为一次全库检索。

每次接续重新按当前截止日检查日期资格，保留已过期条目的历史身份及原文记录。阅读日志有效且来源未改变时可复用，不要求每图从头通读全部文献。

脚本的图任务覆盖只反映来源记录中的linked_figure_tasks标签，不等于最终逐句映射已完成。sources_mapped阶段仍须实际给出原文位置、本稿表达及本研究证据链接，不能由条目数或标签覆盖自动升级。
